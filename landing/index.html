One endpoint. Every free key taking turns.

Most providers hand you a small free tier. Pool-anything gathers N keys for the same provider into a single pool, then round-robins through them, tracks usage per key, and forwards requests with the right header. Zero dependencies, SQLite, self-hosted.

Start pooling locally
npm install && npm run dev — open :3000

37 providers preconfigured. Custom providers are one JSON row. Keys stay in local SQLite, masked everywhere except one view.

    Your app talks to one place. The pool does the turn-taking.

    Post to /api/pools/:id/proxy and pool-anything picks the next key, injects the auth header, forwards to the provider, and records usage. The cursor is just cursor % keys.length, so load spreads evenly.

    Drop-in proxy call

    No SDK. Send the path, method, and body — the pool adds the key and counts the tokens you declare.

    # rotate + proxy in one call
curl -X POST localhost:3000/api/pools/1/proxy \
  -H 'content-type: application/json' \
  -d '{"path": "/chat/completions",
      "method": "POST",
      "body": {"model": "llama-3.3-70b",
               "messages": [{"role":"user",
                             "content":"hi"}]},
      "tokens": 25}'

    Run it on your machine

    1. Install dependencies with npm install.
    2. Start with npm run dev and open http://localhost:3000.
    3. Search a provider, paste keys, hit Gather. Your pool is live.
    4. Send traffic through /api/pools/:id/proxy or the Playground.

    Good to know before you expose it

    1. Keys live in data/pool-anything.db, which stays out of version control.
    2. List endpoints return masked keys. Raw keys need the single-key view.
    3. There is no auth built in — keep it on localhost or behind your own gate.

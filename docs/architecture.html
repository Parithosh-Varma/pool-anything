Architecture

A deliberately small system: two HTTP servers, one SQLite file, one JSON registry, zero runtime dependencies.

Project layout

pool-anything/
├── src/
│   ├── server.ts          # main server: UI pages + JSON API + proxy  (:3000)
│   ├── pool/
│   │   └── index.ts       # core: schema, providers, rotation, usage, targets
│   ├── db/
│   │   ├── index.ts       # secondary "items" table + dbPing()
│   │   └── init.ts        # db:init CLI (--seed)
│   ├── sandbox/
│   │   └── server.ts      # localhost-only test server + minimal UI   (:4000)
│   └── logo.png
├── data/
│   ├── providers.json     # provider registry (36 providers)
│   └── pool-anything.db   # SQLite — gitignored
├── public/logos/          # provider logos + manifest.json
├── docs/                  # this documentation site
└── package.json           # scripts: dev, build, db:init, sandbox…

src/pool/index.ts is the heart of the system — both servers import the same functions, so behavior is identical between the main API and the sandbox.

Rotation

Each pool has a persistent integer cursor. Rotation is a single round-robin step:

keys   = SELECT … FROM pool_keys WHERE pool_id = ? ORDER BY id
pick   = keys[cursor % keys.length]
cursor = cursor + 1          // committed immediately
  • Fair by construction — every key gets a turn before any key gets a second.
  • State lives in the database, not in memory, so rotation survives restarts.
  • nextKeyRaw() returns the raw key (used by the proxy); nextKey() strips it and returns only masked metadata (used by the API).
  • Removing a key shifts the index set — harmless, since the cursor just wraps over the new list.

Proxy flow

POST /api/pools/:id/proxy runs this sequence:

  1. Resolve the target — pool overrides (base_url, key_header, key_prefix) win over the provider registry; otherwise the registry value is used.
  2. Pick the next key via nextKeyRaw() (advances the cursor).
  3. Inject credentials — either a header (Authorization: Bearer …, x-api-key, custom prefix) or a query parameter (query:access_token style), plus provider extraHeaders and caller-supplied headers.
  4. Forward with native fetch: method, JSON body, computed headers → baseUrl + path.
  5. Record usage — if the caller passed a positive tokens, insert a row into usage against that key.
  6. Respond with key_id, label, masked, status and the upstream body (capped at 4000 chars). Network failures return 502 with the error detail.

Storage

One SQLite file (data/pool-anything.db) via Node's built-in node:sqlite (DatabaseSync) — a local stand-in for Cloudflare D1. Schema is created idempotently at startup; extra columns are added with guarded ALTER TABLE migrations.

CREATE TABLE pools (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  provider TEXT NOT NULL,          -- registry id, e.g. 'groq'
  name TEXT NOT NULL,
  cursor INTEGER NOT NULL DEFAULT 0,      -- rotation position
  base_url TEXT NOT NULL DEFAULT '',      -- override (custom providers)
  key_header TEXT NOT NULL DEFAULT 'X-API-Key',
  key_prefix TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE pool_keys (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pool_id INTEGER NOT NULL REFERENCES pools(id) ON DELETE CASCADE,
  label TEXT NOT NULL,
  api_key TEXT NOT NULL,           -- stored plaintext
  info TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE usage (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pool_id INTEGER NOT NULL REFERENCES pools(id) ON DELETE CASCADE,
  key_id INTEGER NOT NULL REFERENCES pool_keys(id) ON DELETE CASCADE,
  tokens INTEGER NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

Aggregates (used, perKey, remaining) are computed on read with SUM() / LEFT JOIN — no denormalized counters to drift.

D1 note: the items table used by /api/db/ping and npm run db:init is a separate demo table for exercising the local-D1 path; pools don't use it.

Provider registry

data/providers.json is a flat array; unknown/malformed entries are filtered out, and a small built-in fallback list applies if the file can't be read at all.

FieldMeaning
id · nameRegistry key and display name.
baseUrlUpstream root; the proxy appends the caller's path.
keyHeader · keyPrefixWhere the key goes: a header name (+ optional prefix like Bearer ) or query:<param>.
extraHeadersAlways-sent headers (e.g. anthropic-version).
quotaHuman-readable free-tier notes, shown in the UI.
keyFieldsInput shape — ["api_key"] or multiple fields (Twilio: SID + token).
hint · docsUrlWhere to get a key; official docs link.
logoPath under public/logos/.
poolabletrue (default), false (control-plane only, e.g. Neon), or "conditional" (Supabase, Appwrite).

Adding a provider = adding one JSON object. Adding a custom provider at runtime = create a pool with your own base_url / key_header / key_prefix.

Security

  • Keys are stored plaintext in SQLite; the file and its WAL/journal siblings are gitignored.
  • List endpoints return masked keys only; GET /keys/:id returns the full value (used by the UI's View button).
  • The API has no authentication — it's a localhost tool. Don't expose :3000 publicly without a reverse proxy and auth.
  • The sandbox binds 127.0.0.1 only.
  • Logo serving validates filenames against ^[a-z0-9-]+\.(svg|png)$; request bodies are capped at 1 MB.
  • Upstream responses are passed through as text (capped at 4000 chars) — treat them as untrusted data.

pool-anything

Gather API keys from any provider into a pool, rotate them round-robin, track usage against each key's quota, and send every request through a single proxy endpoint.

What it is

Most API providers give you per-key rate limits — requests per minute, tokens per day, credits per month. One key runs out; ten keys give you ten times the headroom. But juggling keys in your app is messy: you need storage, rotation logic, failure handling, and visibility into who used what.

pool-anything is a small self-hosted service that does exactly this and nothing else:

  • Pool — collect N API keys for the same provider under one named pool.
  • Rotate — hand out keys round-robin so load and quota consumption spread evenly.
  • Proxy — forward your request to the provider with the right key injected (header or query param), and report which key served it.
  • Track — record usage per key so you can see consumption against quota at a glance.

It ships with a registry of 36 preconfigured providers (Groq, OpenRouter, Gemini, OpenAI, Anthropic, Cohere, ElevenLabs, Tavily, Mapbox, Supabase and more), a web UI for managing pools and keys, and a JSON API for everything else. Zero runtime dependencies — Node.js built-ins only, with SQLite as a local Cloudflare D1 stand-in.

How it works

1 · GatherSearch a provider in the UI, paste one or more API keys into its pool. 2 · ProxyPOST to /api/pools/:id/proxy with a path and body. The next key is picked automatically. 3 · RotateA cursor advances on every call, so keys take turns evenly. Usage is recorded per key. 
# one request, whatever key's turn it is
curl -X POST http://localhost:3000/api/pools/1/proxy \
  -H 'content-type: application/json' \
  -d '{"path":"/chat/completions","method":"POST",
       "body":{"model":"llama-3.3-70b","messages":[{"role":"user","content":"hi"}]},
       "tokens":24}'

The response tells you the upstream status, the body (truncated to 4000 chars), and exactly which key served the request:

{ "key_id": 3, "label": "key 2", "masked": "gsk_…ab", "status": 200, "body": "{…}" }

Features

FeatureDetails
Provider registry36 providers with base URL, auth style, required headers, free-tier quota notes and logos — editable in data/providers.json.
Round-robin rotationPersistent per-pool cursor; GET /next or let the proxy rotate for you.
Auth injectionHeader keys (Authorization: Bearer …, x-api-key, xi-api-key…) and query-param keys (?access_token=, ?key=, ?appid=).
Usage trackingRecord tokens per request; per-key and per-pool totals with quota math.
Web UIProvider search, pool setup dialog, pools overview, full key manager (view / edit / remove).
SandboxA second, localhost-only server (:4000) with a minimal UI for exercising pools safely.
Zero depsNo npm runtime dependencies. TypeScript + node:sqlite + built-in fetch.
Custom providersAnything not in the registry: give it a base URL and key header and pool it.
Not for production key custody. Keys are stored in a local SQLite file and returned in full by the single-key endpoints. Run pool-anything on a machine you trust, like any other secrets tool.
